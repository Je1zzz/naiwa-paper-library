# 安装与自动连接验收

日期：2026-10-23。平台：Windows，Obsidian 1.14.4，Zotero 10.0.6。

结论：在本机使用独立新建的 vault，从 GitHub 实际下载 ZIP 后安装、首次信任、首页启动、Zotero 附件导入、OpenCodex 供应商发现及实际 AI 请求均通过。本机已安装并配置 Zotero、OpenCodex 和 Codex；这不是一台未安装任何外部应用的新系统。

## 实际测试

1. 下载公开仓库的 `main.zip`，完整解压到新 vault 之外；直接运行下载副本中的根目录 `install.cmd -VaultPath <新建目录>`。没有复制开发目录，也没有执行 npm 构建。五个运行文件通过 SHA256 校验。
2. 在 Obsidian 中首次打开新 vault，实际出现「信任仓库作者并启用插件」提示。确认后插件加载，文献首页自动打开，初始文献数为零。测试没有关闭其他知识库或关闭系统安全设置。
3. 第一轮下载版本 `ac7baca` 暴露了问题：自动连接已登录 Codex 后，OpenCodex 的其他供应商未发现。修复提交 `a103c62` 后，重新从 GitHub 下载该提交 ZIP，在另一个全新 vault 重走安装与首次启动。
4. 修复后的首次启动同时识别 Codex 登录，以及 OpenCodex 的 DeepSeek、OpenRouter 配置。供应商列表包含三者；当前已可用的默认 Codex 选择保持不变。凭据按需读取，插件 `data.json` 中没有 API key/token 字段。
5. 通过真实文献首页的「Zotero 导入」搜索条目。该条目有两个 PDF，界面没有擅自默认勾选，手动选择第二个附件。结果只导入一个 PDF，内容与选定 Zotero 本地附件逐字节一致，生成关联笔记并保存 Zotero 链接。
6. 从新 vault 的插件接口发出两次简短真实请求：OpenCodex 关联的 DeepSeek，以及本机 Codex，均准确返回测试短句。没有发送个人 PDF 全文。这些调用使用现有账号的正常额度。
7. 实际请求供应商模型列表成功：DeepSeek 返回 2 个模型，OpenRouter 返回 468 个模型。数量是本次测试快照，可能随后变化；没有将获取模型列表等同于每个模型都有可用权限或额度。
8. 重载新 vault 后，PDF、关联笔记、三种供应商和两个 OpenCodex 关联均保留，首页正常打开，无须再次输入凭据。

安装器的进程检测也已修正：OpenCodex 桌面进程存在但不在 PATH 时，不再误报为未检测到运行应用。

## 回归与边界

Node 测试套件通过 66 项，3 项可选公网书目测试跳过。包含中文/带空格目录、重复安装保留数据、注册 vault 选择、取消、DryRun、校验失败、危险路径拒绝，以及 Codex/OpenCodex 并存、仅 OpenCodex、保留自定义连接和缺少外部应用的情况。缺少外部应用的场景使用模拟测试，没有为此卸载用户应用。

Zotero 本地 API 导入不需要配套 XPI。Zotero 右键导入菜单属于可选扩展，本轮没有在用户 Zotero profile 中安装/重装 XPI，也不据此宣称其安装菜单已实测。账号登录、受限模式信任和 XPI 安装仍由使用者确认，安装器不替用户创建账号或绕过权限。

尚未在另一台物理电脑、macOS 或 Linux 重做实机验收。新电脑请按 [迁移与开发说明](NEW-COMPUTER.md) 安装外部应用并恢复账号。自动连接不会提供新的免费额度。
